# 数据保存与发布边界

本项目是研究代码和公开派生结果仓库，不是原始行情数据仓库。原始数据由
`quant-market-data-platform` 管理；完整研究运行结果放在仓库外的稳定输出目录。

## 分层

| 层级 | 内容 | 推荐格式 | 位置 |
| --- | --- | --- | --- |
| 原始数据 | 逐股票逐日行情、估值、复权和状态字段 | Parquet | `quant-market-data-platform` |
| 研究中间结果 | 大型面板、逐股票逐日结果、可重复计算缓存 | Parquet / DuckDB | 仓库外输出目录 |
| 公开派生结果 | 年度汇总、分位数、降采样曲线和已审查指标 | CSV / JSON | `web/public/data` |
| 研究说明 | 口径、来源、覆盖区间、限制 | Markdown / JSON | Git 仓库 |

不要把供应商原始数据、凭证、完整行情面板或机器路径提交到本仓库。

## CSV 与 Parquet 的选择

CSV 适合小型公开结果：人工可读、Git diff 清晰、浏览器和静态页面无需额外解析器。
Parquet 适合大型分析数据：字段类型明确、压缩率高，DuckDB 可以按列和按条件读取。
浏览器如果需要直接查询 Parquet，可以使用 DuckDB-WASM 或 Apache Arrow，但这不改变
Git 对二进制文件难以逐行审查的事实。

因此大型结果采用 `Parquet + manifest + 小型摘要 CSV/JSON`，而不是把 Parquet
直接作为页面唯一数据源。

## 体量阈值

这些是维护阈值，不是硬性协议：

- 单个派生文件小于约 10 MB：CSV 通常足够；
- 单个文件约 10–50 MB：考虑压缩、拆分、降采样或只发布摘要；
- 单个文件超过约 50–100 MB：停止提交 Git，改放外部 Parquet/对象存储；
- 全部公开派生数据达到约 50 MB：重新审查页面发布边界；
- 原始逐股票逐日数据无论大小都留在外部数据平台。

当前仓库的公开派生数据只有几 MB，不需要批量迁移格式。新增研究应优先保持稳定
文件名覆盖刷新，避免每次生成一个带日期的新副本。

## Manifest 要求

大型或重要研究输出至少记录：

- schema/version；
- 生成时间；
- 数据来源和覆盖区间；
- 行数和关键筛选口径；
- 输出文件格式、大小和校验和；
- 是否为原始数据或已审查的派生数据。

例如微盘成交额报告生成：

- `smallcap_turnover_daily.csv`：完整的每日 N 只汇总，保存在仓库外；
- `smallcap_turnover_summary.json`：覆盖区间和研究限制；
- `smallcap_turnover_manifest.json`：schema、文件大小、行数和 SHA-256。

2008 年起的扩展版本使用不同的历史数据源，文件名加上 `history` 后缀，并在 summary
和 manifest 中标记 `quality_status = incomplete`。这是因为历史源没有可靠的 ST 和停牌
字段；它可以作为长期描述性序列，但不能与 2015 年后的清洗版本直接混为一个质量等级。

页面如需展示，只应复制经过审查的摘要或降采样结果到 `web/public/data`，不发布完整
逐股票逐日面板。
